# MD2DOC-Evolution 完整使用教學

這份教學以「從 Markdown 到可交付 Word 書稿」為主線，說明網站操作、語法、版型選擇、AI 轉稿，以及匯出後必須在 Word 完成的換頁與交付檢查。

## 1. 三分鐘快速開始

1. 在左側編輯區貼上或匯入 UTF-8 Markdown。
2. 從「範例」選單載入中文快速範例，先熟悉章首頁、標題、對話與 callout。
3. 按「版面設定」，選擇文件 Profile、紙張大小與邊界。
4. 在右側連續白底預覽檢查內容結構。預覽不模擬最終 Word 分頁。
5. 先下載 Markdown 備份，再下載 DOCX。
6. 在 Word 更新目錄與欄位，調整少數換頁點，最後輸出 PDF 逐頁檢查。

> 不要用大量空行、連續 Enter 或假清單來推動版面。這些做法在字型或印表機變動後很容易重新跑版。

## 2. 編輯器與匯入方式

網站提供三種輸入方式：

- 直接在編輯器輸入或貼上 Markdown。
- 按「匯入」選擇 `.md` 檔案；匯入會取代目前稿件，因此系統會先要求確認。
- 按「匯入」選擇圖片，或把圖片拖入編輯區；圖片會登錄在本次瀏覽器工作階段並插入 Markdown 圖片語法。

「插入」選單與桌機左側工具列使用同一份命令規格，包含文件結構、清單、提示、對話、媒體與技術內容。手機與平板可直接使用「插入」選單，不需要桌機側欄。

瀏覽器會在本機儲存目前草稿與部分設定。敏感書稿仍應使用受管理的裝置，完成後可按「重設」清除目前草稿，並自行清除瀏覽器網站資料。

## 3. 建議的文件結構

一份出版社書稿建議依照以下順序：

```markdown:no-ln
---
title: "書名"
author: "作者"
header: true
footer: true
---

[TOC]

[CHAPTER]
number: "01"
title: "第一章標題"
summary: "本章摘要。"
goals:
  - "本章完成目標。"
[/CHAPTER]

# 文件主標題

## 第一節

正文內容。
```

Frontmatter 必須放在第一行。`[TOC]` 會在 Publisher Profile 產生 Word 原生目錄欄位；匯出後仍要在 Word 更新欄位。`[CHAPTER]` 描述章首頁內容，不是用空白段落模擬換頁。

## 4. 常用 Markdown 與出版語法

| 用途 | 語法 | 注意事項 |
| :--- | :--- | :--- |
| 標題 | `#`、`##`、`###` | 只使用 H1 到 H3 |
| 無序清單 | `- 項目` | 只有真正清單才會有黑點 |
| 編號清單 | `1. 步驟` | Word 使用原生編號 |
| 待辦清單 | `- [ ]`、`- [x]` | 匯出為 `☐`、`☒`，不使用黑點 |
| 引用 | `> 內容` | 一般引用段落 |
| 提示框 | `> [!NOTE]` | 支援 NOTE、TIP、WARNING、IMPORTANT、CAUTION |
| 程式碼 | 三個反引號加語言 | 可加 `:ln` 或 `:no-ln` |
| Mermaid | ` ```mermaid ` | 預覽與 DOCX 會渲染成圖 |
| 圖片 | `![說明](圖片識別碼)` | 建議先由網站匯入圖片 |
| QR | `[QR:標籤](URL)` | 必須獨占一行，只用於紙本掃描 |
| 連結 | `[文字](URL)` | 一般連結保持 hyperlink |
| 底線 | `<u>文字</u>` | 這是唯一支援的 HTML-like inline 語法 |

角色對話語法：

```markdown:no-ln
使用者 ":: 這是左側角色的對話。
AI ::" 這是右側角色的回覆。
系統 :": 這是置中的系統訊息。
```

匯出 Word 時，角色名稱會先獨立一行，再顯示對話內容，並保留易讀的段落間距。不要在角色名稱前加 `-`，否則它會成為真正的無序清單。

## 5. 範例稿件與功能覆蓋

「範例」選單提供四份由單一來源管理的稿件：

- 中文快速範例：用最短篇幅體驗主要出版流程。
- 中文完整功能稿：涵蓋 Parser、Preview 與 DOCX 的所有正式支援語法。
- English quick example：英文快速流程。
- English complete manuscript：英文完整功能覆蓋。

教學中心可直接下載中文完整功能稿的 Markdown 與 `publisher-narrow` DOCX。若要確認某項語法是否正式支援，以完整功能稿、網站插入選單與 GitHub 語法矩陣三者一致為準。

## 6. 紙張、邊界與 Profile

預設技術書尺寸為 17.6 × 23.6 公分，也可選 A4、A5、B5 或自訂尺寸。

| 邊界方案 | 上下左右或裝訂設定 | 建議用途 |
| :--- | :--- | :--- |
| 窄邊界 | 四邊 1.27 cm | 內容密度高、先看整體篇幅 |
| 緊湊 | 四邊 1.50 cm | 較窄但仍保留呼吸感 |
| 平衡 | 四邊 2.00 cm | 一般閱讀與內部文件 |
| 標準 | 四邊 2.54 cm | 常見辦公文件 |
| 出版社精確 | 上下 2.10、左右 2.30 cm | 對齊目前出版社書稿幾何 |
| 裝訂鏡像 | 上 2.00、下 2.20、內 2.20、外 1.80、裝訂 0.50 cm | 雙面印刷與裝訂預留 |

Profile 的定位：

- `publisher-exact`：新版預設，固定採出版社精確邊界。
- `publisher-narrow`：採窄邊界，增加內容寬度。
- `publisher-binding`：鏡像邊界與裝訂預留。

同一份內容換 Profile 後，頁數改變是正常現象。請先決定交付版型，再做 Word 最後換頁。

## 7. AI 轉稿提示 v2

網站的「AI 轉稿提示」提供兩種模式：

- 轉換既有稿件：保留原始事實、程式碼與來源，只整理結構。
- 建立新稿初稿：依主題、讀者與可信素材建立初稿，缺少資訊一律標示「待補」。

建議流程：

1. 複製適合的提示詞。
2. 將提示詞與原始稿件或書稿 brief 交給 AI。
3. 要求 AI 只回傳 Markdown，不包外層 code fence。
4. 貼回 MD2DOC-Evolution。
5. 用完整預覽與匯出前警告檢查結構。
6. 人工核對事實、引用、程式碼與圖片授權。

AI 不應決定 Profile、紙張、邊界與最終頁碼，也不應靠大量空行模擬換頁。

## 8. Word 後製與換頁專章

MD2DOC-Evolution 負責穩定的內容結構與出版樣式，但 Word 的實際分頁仍會受到字型版本、Word 版本、印表機驅動、圖片尺寸及目錄更新影響。最終交付前應保留一輪人工後製。

### 8.1 先更新目錄與欄位

1. 在 Word 按 `Ctrl + A` 全選。
2. 按 `F9` 更新所有欄位。
3. 目錄出現選項時，第一次或標題有變更請選「更新整個目錄」。
4. 表格中的公式或欄位可能需要逐表選取後再按 `F9`。

Microsoft 官方說明：[Update fields](https://support.microsoft.com/en-us/word/update-fields)

### 8.2 開啟格式標記

按 `Ctrl + Shift + 8` 顯示段落記號、手動分頁與分節符號。這一步可以分辨：

- 真正的項目符號清單。
- 空白段落或多餘 Enter。
- 手動分頁。
- 下一頁、奇數頁、偶數頁或連續分節符號。
- 被設定「段前分頁」的段落。

一般正文、章標題、角色名稱或 callout 前方若出現黑點，通常代表該段落被套用了清單或分頁相關段落設定；本工具的新輸出只會讓真正的無序清單產生黑點。

### 8.3 用段落分頁設定，不用空行推版

選取標題或相關段落，開啟「段落」對話框的「分行與分頁」：

- 與下段同頁：避免小標題孤單留在頁尾。
- 段中不分頁：讓短段落完整留在同一頁。
- 段前分頁：讓特定標題從新頁開始。
- 孤行控制：避免單獨一行留在頁首或頁尾。

Microsoft 官方說明：[Keep text together in Word](https://support.microsoft.com/en-US/Word/keep-text-together-in-word)

### 8.4 何時使用分頁與分節

只需要下一頁時，優先使用段前分頁或一般分頁。需要改變頁首頁尾、頁碼、欄數、方向或奇偶頁章首頁時，才使用分節符號。

- 下一頁分節：新章或新版面從下一頁開始。
- 連續分節：同一頁內改變欄數等格式。
- 奇數頁／偶數頁分節：紙本書章節固定從指定奇偶頁開始，可能刻意產生空白頁。

Microsoft 官方說明：[Insert a section break](https://support.microsoft.com/en-us/word/insert-a-section-break)

### 8.5 建議的逐頁修整順序

1. 先確定紙張與邊界，不再變更 Profile。
2. 更新目錄與所有欄位。
3. 檢查章首頁是否從正確頁開始。
4. 檢查 H2、H3 是否落在頁尾。
5. 檢查角色名稱與第一段對話是否同頁。
6. 檢查表格是否被不自然地切開。
7. 檢查圖片、圖說、QR 與 Mermaid 是否完整。
8. 檢查程式碼區塊是否需要整塊移到下一頁。
9. 開啟格式標記，移除多餘空白段落與非預期手動分頁。
10. 再更新一次欄位，輸出 PDF 後逐頁複查。

## 9. 匯出前與交付前檢查

匯出前：

- Frontmatter 有 title 與 author。
- Markdown 圖片都已登錄或使用有效來源。
- Mermaid 可以在預覽完成渲染。
- 一般連結沒有誤寫成 QR。
- 角色對話沒有加清單符號。
- 只有真正清單使用 `-` 或 `1.`。

Word 交付前：

- 紙張為預定尺寸，邊界與裝訂設定正確。
- 目錄、頁碼、頁首與頁尾已更新。
- 格式標記檢查沒有無效黑點或多餘空白段落。
- 表格、圖片、程式碼與章首頁已逐頁檢查。
- PDF 的總頁數、空白頁與最後一頁符合預期。
- 保留一份未壓縮的 DOCX 與原始 Markdown。

## 10. 能力邊界、隱私與已知限制

- 右側是連續內容預覽，不是 Word 分頁模擬器。
- 網站無法保證不同 Word 版本、字型與印表機環境得到完全相同頁碼。
- Word 原生目錄必須在桌面版 Word 更新。
- Mermaid 與圖片匯出需要瀏覽器完成渲染；超過安全 Canvas 上限的 Mermaid 會停止匯出並顯示警告，請簡化或拆分圖表。
- 複雜跨頁表格、索引、交叉引用、腳註、文獻管理與出版社專屬巨集仍需在 Word 後製。
- 稿件主要在瀏覽器本機處理；遠端圖片預設不載入，按下「載入遠端圖片」後才會以 `no-referrer` 請求。字型、AI 工具與部署環境仍可能產生其他第三方網路請求。
- Frontmatter 與單一 `[CHAPTER]` YAML 區塊上限為 256 KiB；正文與大型資料請放在 metadata 區塊之外。
- 使用 AI 前應先移除機密、個資與未公開商業內容，並遵守所使用 AI 服務的資料政策。

遇到問題時，請先用中文完整功能稿重現，再附上 Markdown 最小範例、所選 Profile、紙張、邊界與 Word 版本回報。
